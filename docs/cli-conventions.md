# DSO CLI conventions (Phase 1–2 remediation)

Authoritative behaviour of the CLI as of this change. Per-command flags live in
[`cli-reference/`](cli-reference/dso.md) (generated by `make docs`).

## Exit codes and error output

| Situation | Exit | Output |
|---|---|---|
| Success, `--help`, `help`, `completion`, bare group (`dso secret`) | 0 | stdout |
| Unknown subcommand, bad/missing arguments, bad flag | 1 | one `Error: …` line on stderr |
| Runtime failure | 1 | one `Error: …` line on stderr, no usage dump |
| `status`: agent unreachable or degraded | 1 | status report on stdout (or JSON), reason on stderr |

Errors are printed once, by `cli.Run`; command code returns errors and never
calls `os.Exit` (enforced by `TestNoOsExitOutsideEntrypoint`). Results go to
stdout, diagnostics and warnings to stderr.

Known exceptions: `dso agent` is a long-running daemon that terminates through
its logger (`logger.Fatal`) on startup failure; `dso logs` helpers print
errors themselves. Both are tracked as follow-ups.

## Secret input

* `secret set`, `inject`: values come from a hidden prompt or stdin — **bytes are
  stored exactly**. `echo x | dso secret set p/k` stores `x\n`; use
  `printf %s x |`, `< file`, or `--trim-newline` (removes exactly one trailing
  `\n` / `\r\n`, nothing else).
* Values must be valid UTF-8, non-empty, ≤ 1 MB. Whitespace-only values are accepted.
* `inject --value` still works but is **unsafe for real secrets**: command-line
  arguments appear in shell history, process listings, CI logs and diagnostics.
  It prints a warning (never the value). Prefer `--value-stdin` or the prompt.
* `secret get/set` without `<project>/` use the legacy default project `global`
  (shared by `set`, `get`, `list`, `env import`); a note is written to stderr.

## Configuration resolution

Highest priority first:

1. `-c/--config` (honoured even when the value is `dso.yaml`)
2. `/etc/dso/dso.yaml`
3. `./dso.yaml`
4. `~/.dso/dso.yaml` — new, used only when none of the above exist

System-over-local is kept deliberately for compatibility with existing
installs. `dso config path [--json]` prints the selected file, why, and any
existing files that were ignored; it never prints contents. Mixed
local-vault + cloud-config hosts default to **cloud** mode (as before); the
notice is printed once and explains `--mode=local` / `DSO_MODE=local`. The
legacy secret-mapping notice is printed once per file per process.

`~/.dso/dso.yaml` is the only absolute path outside DSO's system directories
that `LoadConfig` accepts; all other path-safety rules are unchanged. The
agent's owner-ID persistence path does not use it.

## Machine-readable output

`--json` exists on `status`, `doctor`, `validate`, `config path`. Contract:
stdout is exactly one JSON document, diagnostics stay on stderr, secret values
never appear, and a non-zero exit still carries the document. `status` keys:
`runtime{mode,version,commit?,uptime?,start_time?}`, `agent_reached`,
`agent_error?`, `providers?`, `cache`, `rotations`, `degraded_services`,
`state` (`healthy|degraded|unavailable`), `health`. Unverifiable fields are
omitted, not guessed. `status -q` prints nothing; use the exit code.
`--no-color` / `NO_COLOR` strip ANSI colour from `watch` and `logs`.

## Command hierarchy: current state and recommendation

Overlaps found (none removed in this phase):

| Purpose | Current commands | Recommended target |
|---|---|---|
| First-time setup | `setup`, `bootstrap local\|agent`, `system setup`, `init` | `setup` (wizard) is the entry point; `bootstrap` = scripted form; `init` = vault only → document as `secret init` alias later |
| Health | `status`, `doctor`, `system status` | `status` = live agent state; `doctor` = environment diagnosis; `system status` = systemd unit only |
| Validation | `validate`, `config validate`, `doctor` | `config validate` = config file only; `validate` = whole project (config + compose) |
| Logs | `logs`, `system logs` | `logs` (journald/REST); `system logs` → alias |
| Local vault | `init`, `secret`, `env import` | keep; group under `secret` |
| Central store | `central …` (experimental) | keep separate from the local vault |

Removal or renaming needs a deprecation-alias release first; check scripts and
docs (`docs/*.md`, `examples/`) before any change.

## Not implemented (do not rely on)

`dso diff` has no comparison logic: it now exits 1 with "not implemented"
instead of claiming "no differences". Remote login, service tokens, secret
history and `dso run` are future work requiring API/store/authorization design.
